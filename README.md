# Keitaro wrapper

Обёртка над рекламным трекером Keitaro: FastAPI + SQLAlchemy + Alembic, фронт на чистом JS.

1. **Создание кампании.** На вход: название, гео (один или несколько кодов стран ISO: `AU` или `MX,AU,RO`) и оффер (поиск с автодополнением). Кампания создаётся с доменом, группой и источником (значения по умолчанию ищутся по именам из `.env`: `DEFAULT_DOMAIN`, `DEFAULT_GROUP`, `DEFAULT_SOURCE`; в форме можно выбрать другие) и двумя потоками:
   - поток 1: фильтр «страна = гео» → редирект на `https://google.com`;
   - поток 2: все остальные → выбранный оффер (100%).

   К имени автоматически добавляется префикс `test_khristoforov_`.
2. **Редактор кампании** — повторяет логику из видео ТЗ:
   - **Fetch streams** загружает потоки из Keitaro. Потоки без офферов показываются просто как поток. Если есть неопубликованные правки, перед загрузкой спрашивает подтверждение.
   - **Добавить оффер**: доли пересчитываются поровну (3 оффера → 34/33/33, 4 → 25/25/25/25), поток желтеет — изменения ещё не в Keitaro.
   - **Push** публикует поток в Keitaro. **Cancel** откатывает к опубликованному: новые офферы удаляются, остальные возвращают долю, статус и закрепление.
   - **Remove**: оффер сереет, доля 0%. После Push он пропадает из Keitaro, но остаётся у нас в архиве. **Bring back** возвращает его в поток.
   - Если оффер удалили прямо в Keitaro, следующий Fetch streams переносит его в архив, откуда его можно вернуть.
   - **Pin** закрепляет долю оффера (можно задать своё значение). Остальные пересчитываются так, чтобы сумма была 100%.

## Запуск

Нужен Python 3.11+.

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
copy .env.example .env            # и вписать KEITARO_API_KEY
alembic upgrade head              # создать схему БД
uvicorn app.main:app --reload
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env              # и вписать KEITARO_API_KEY
alembic upgrade head
uvicorn app.main:app --reload
```

Открыть http://127.0.0.1:8000. Swagger со всеми ручками: http://127.0.0.1:8000/docs.

API-ключ Keitaro: админка → Профиль → API ключи. Ключ хранится только в `.env`, в репозитории его нет. Без ключа приложение запускается и тесты проходят, но интерфейс не загрузит данные из Keitaro.

## База данных и миграции

По умолчанию — SQLite-файл `wrapper.db` в корне проекта, ничего ставить не нужно. Для PostgreSQL (драйвер `psycopg` уже в зависимостях) — в `.env`:

```
DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/keitaro_wrapper
```

URL базы Alembic берёт из `DATABASE_URL` (`alembic/env.py`), в `alembic.ini` его прописывать не нужно.

- Применить миграции: `alembic upgrade head`
- Откатить последнюю: `alembic downgrade -1`
- После изменения моделей в `app/models.py`: `alembic revision --autogenerate -m "что поменялось"`, затем `alembic upgrade head`

Миграции проверены на SQLite и PostgreSQL 16: `upgrade head` → `downgrade base` → `upgrade head`, `alembic check` без расхождений.

Таблицы:

| таблица | что хранит |
|---|---|
| `campaigns` | кампании (id = id в Keitaro), гео, создана ли обёрткой |
| `streams` | потоки кампании: позиция, schema из Keitaro, есть ли офферы |
| `offers` | кэш названий офферов Keitaro |
| `stream_offers` | привязка оффера к потоку: черновик (`share`, `state`, `pinned`) и опубликованная версия (`published_share`, `published_state`, `published_pinned`) |

Поток считается неопубликованным (жёлтым), если доля или статус хоть одной привязки отличается от опубликованной версии. Push копирует черновик в опубликованную версию, Cancel — наоборот.


## Как обёртка бережёт данные в Keitaro

- **Push сверяется с Keitaro.** Перед публикацией поток перечитывается. Если его поменяли в Keitaro после нашего Fetch, Push отказывает (409) и просит сделать Fetch, а не затирает чужую правку.
- **Push не публикует пустой поток** и поток с суммой долей не 100%.
- **Выключенные в Keitaro офферы** (`state: disabled`) показываются серыми, не участвуют в пересчёте и при Push отправляются обратно как есть. Keitaro сам сумму долей не проверяет (принимает и 150%), а трафик получают только активные офферы — поэтому обёртка следит, чтобы ровно 100% давали активные.
- **Fetch чинит неверную сумму.** Если в Keitaro активные офферы дают не 100% (например, один удалили руками), после Fetch поток сразу пересчитан в черновике и подсвечен как неопубликованный — остаётся нажать Push.
- **Ошибки Keitaro и сети** отдаются как 502/504 с понятным текстом.
- **Если после создания кампании не загрузились потоки,** кампания всё равно возвращается: повторное нажатие не создаст дубль.

## Безопасность

- Авторизации нет: обёртка рассчитана на локальный запуск (`uvicorn` по умолчанию слушает 127.0.0.1). **Не запускайте её с `--host 0.0.0.0`** без reverse-proxy с авторизацией — иначе любой в сети сможет править кампании ключом из `.env`.
- Изменяющие запросы (`POST/PUT/DELETE /api/...`) требуют заголовок `X-Requested-With: keitaro-wrapper` — чужой сайт, открытый в том же браузере, не может его отправить (CORS не разрешён), так что CSRF не пройдёт.
- Запросы с чужим `Host` отклоняются (защита от DNS-rebinding). Список — `ALLOWED_HOSTS` в `.env`.
- Ключ Keitaro есть только в `.env` и в заголовке запросов к Keitaro; в ответы API, логи и фронт он не попадает. `KEITARO_URL` принимается только с `https://` (http — только для localhost), чтобы ключ не ушёл открытым текстом.
- Страница отдаётся с `Content-Security-Policy` (только свои скрипты и стили, без inline) — дополнительная защита от XSS поверх экранирования.
- `pip-audit -r requirements-dev.txt` — известных уязвимостей нет (19.11.2026).
- Проект прогнан через [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) (профиль quick, только по исходникам): подтверждённых уязвимостей нет; советы по усилению применены.

## Допущения и ограничения

- Поток 1 отправляет на Google трафик **из** выбранных стран, поток 2 — всех остальных на оффер. Так написано в ТЗ и показано на скриншоте (австралийский IP → google.com). Несколько стран — один поток со списком стран в фильтре.
- Доли целые, как в Keitaro. Остаток от деления достаётся первым офферам: 100/3 → 34/33/33.
- Тестовому аккаунту виден один оффер, а в поток Keitaro принимает любой ID. С `ALLOW_UNLISTED_OFFERS=true` редактор и форма создания разрешают такие ID, а в названии оффера помечают, что его нет в списке. По умолчанию выключено (`.env.example`).
- Fetch streams берёт Keitaro за источник правды и сбрасывает неопубликованный черновик (с подтверждением в интерфейсе).
- Нет авторизации и блокировок. Черновик потока общий для всех, кто открыл эту обёртку. Правки, сделанные прямо в Keitaro или из другой копии обёртки, Push замечает (409). Для одновременной работы нескольких байеров в одной обёртке нужны версия потока и `SELECT … FOR UPDATE` на PostgreSQL.
